# Automatic Error Analysis

CONFIG 管理后台的“错误分析 API”负责未知错误的异步分析。当前接入 `https://ai.ravenhash.org/v1/responses`、模型 `gpt-5.6-sol`（按用户要求从 `gpt-5.5` 切换，已实测成功）。该站列出的 `gpt-6-luna` 在当前分组没有可调用账户。模型、协议、接口地址、Key、开关和每日调用上限可在后台修改。

## 流程

1. 两站网关对待适配或未归类的明确失败生成随机 `ea_` 分析回执，正常返回原有失败信息。已明确的参数错误不调用 AI；受理不明和上游账户错误不交给 AI 改写。
2. 网关仅把经过私有渠道词表脱敏的 `analysisInput` 留在私有诊断记录。CONFIG 每分钟从两站管理员接口读取待适配队列，每轮最多收集 10 条、处理 5 个分析任务。
3. 缓存键包含站点、渠道/任务范围、完整脱敏错误（保留所有数值）、分析接口/模型/协议及协议版本。同范围的相同错误只调用一次；模型范围不明确时按任务隔离，不跨渠道猜测。
4. AI 只输出原因、原文依据、固定建议类型和置信度。程序要求依据是输入中的原文片段、置信度不低于 0.85、不出现原文没有的数字、不含敏感内容或受理/计费/重新提交指令。不合格结果只在后台标记待人工查看，不传给客户。
5. 客户通过随机分析回执只读查询结果，单独显示“AI 排查建议”和原错误依据。建议不会覆盖原错误，不改变任务成功/失败、受理、计费状态，也不自动重试生成。分析信息不足时不调用 API。

## 存储与权限

- `/var/lib/flow-config/error-analysis-settings.json`：私有 API 配置，0600 权限。管理员读取只返回 `hasKey`，保存时 Key 留空表示保留，清除需要明确勾选。凭据不进入公开 CONFIG。
- `/var/lib/flow-config/error-analysis-state.json`：队列、缓存、回执关联和每日调用计数，0600，原子替换。默认每日最多 50 次调用；失败尝试也计入上限，自动任务不无限重试。管理员可对失败或未通过校验的结果点击“重试分析”。存储不可读时暂停自动调用，不重新累计预算。
- 默认保留 7 天，最多 2000 个缓存任务、5000 个回执。重启后已经发起但未保存结果的任务标记失败，避免自动重复计费。
- 管理接口 `GET/POST /admin/error-analysis` 需要登录，写操作还要求 CSRF 和同源。公开 `GET /error-analysis/ea_<32hex>` 仅返回经过校验的建议，不包含日志、Key、模型配置或请求身份，也不能触发模型调用。
- 分析服务仅访问公开 HTTPS 域名，DNS 地址检查并固定为公网 IPv4，禁止重定向；45 秒超时、128 KiB 返回上限。支持 Chat Completions 与 Responses 两种 JSON 输出协议。

## 客户端

新增 `diagnostics:error-analysis` IPC；网络查询固定走 CONFIG 主进程接口，渲染层不持有 Key。失败任务每 15 秒检查结果，主进程对相同回执缓存 30 秒，并再次清洗收到的建议。源码版需要重启 Electron；安装版需要升级一次。旧错误记录没有分析回执，不会被伪装成新分析结果。

## 验证

`configserver/error-analysis.test.mjs` 覆盖缓存、重启、预算、站点范围、信息不足、输出越权和凭据；`electron-main/error-analysis-client.test.cjs` 覆盖固定查询与去重；后台 smoke 和 `scripts/customer-error-message-smoke.cjs` 覆盖管理员配置及客户端异步显示。测试 fixture 不发起视频生成；真实 API 连通性检查仅使用不含客户资料的示例错误。
