# 视频成功结果的地址边界

2026-10-06，在 PR #39 的新视频结果去地址改动上补充恢复边界。原有错误脱敏处理失败响应，本改动处理成功结果；两者不能互相替代。

## 输出与恢复

- 普通视频、山海视频、原任务重新查询、下载完成回调不再返回上游 `url` / `video.url`。下载和过期地址刷新继续使用主进程内部数据。
- `publicVideoResult` 给视频成功结果定义固定字段，只放本地文件、任务/项目/节点标识、尺寸和既有用户输入信息。主进程的生成/恢复边界统一调用它；失败响应继续交给已有错误协议，不丢失状态码、受理状态或排查编号。
- 老版恢复记录即使有 `result.url`、`result.video.url` 或原始响应，恢复前也过滤，防止通过 `return {...result}` 再传到界面或 Agent。成功回填后仅更新该检查点的结果，不改原 endpoint、Location、任务 ID、凭据选择或用户提示词。
- 老缓存有本地文件时直接复用，不查询、不重提生成；文件缺失时仍按原账号和任务 ID 查询下载。失败或取消不清空旧记录。
- 视频结果已有本地路径时，渲染端不再保留冗余 `_resultUrl`，避免它继续进入节点结果列表。用户手动输入的链接和参考素材不是供应商生成结果，不做全文 URL 替换。

## 范围

不批量扫描或删除历史 board.json、素材、任务或引用。历史已保存节点不承诺自动清空所有旧 URL；仅本次经过的生成/恢复结果适用。私有恢复路由与管理员诊断仍保留排查和恢复所需信息，不能将它们改成脱敏占位符。

保留既有“正在下载...”状态、字节进度、慢网空闲超时、原任务恢复、StarFrame 鉴权与跨域凭据移除逻辑。没有部署服务器、合并 GitHub PR 或发布安装包。

## 验证

`video-result-privacy.test.cjs` 和 `generation-boundary.test.cjs` 覆盖普通生成、旧缓存本地复用/重新下载、成功回填后的检查点、用户输入不误删、错误协议不变。山海、StarFrame、GlobalAiOpc 和任务恢复相关测试覆盖供应商分支。

`scripts/video-download-progress-smoke.cjs` 使用本地带签名查询参数的视频地址，验证生成完成后停止计时、慢速下载、画布落地，以及 board.json、任务记录、恢复检查点中不出现该上游地址或签名。所有模拟请求都走本地服务，不发生真实生成费用。
